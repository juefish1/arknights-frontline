# 阶段 7 比赛统计、结算与全员同意退出

## 范围与依据

依据 `2026-08-25-3v3-single-lane-graybox-design.md` 第 8、14–19 节与用户 2026-10-01 最新决定，补齐阶段 6 之后的比赛闭环：Windows 平台、取消 15 分钟强制结算、将重新开始改为同队全部同意后退出。Unity 采用 6000.6.2f1；沿用阶段 5 已验收技能与阶段 6 已验收电脑/再部署规则。

本阶段提供比赛时间、双方塔血量、六名干员击杀/死亡/对塔伤害、结算面板与退出投票。不新增经验、经济、助攻、主菜单、选人或联网系统。数值调整只在实际比赛或性能证据表明需要时进行，不能凭空修改已验收战斗值。

## 比赛时间与胜负

- 开局从 0 秒计时，使用受游戏暂停影响的游戏时间；没有时间上限，超过 900 秒仍继续计时和比赛。
- 防御塔摧毁决定胜负，保持现有同帧双塔归零为平局规则；不实现任何超时结算或按塔血量比较胜负。
- `MatchEnding` 继续同步冻结行为；新增一次性的最终结算通知，在同帧塔死亡收集完成、胜负确定并取消残余投射物后发出。
- 停止兵线、电脑、撤退、再部署、技能、持续效果、玩家战斗输入和单位移动。保留结算 UI 的操作能力；不通过修改全局 Time.timeScale 来冻结。
- 比赛结束后时间、结果快照和统计不继续变化。旧 `Tick()` 调用兼容现有测试；计时 API 可通过测试传入确定性时间增量。

## 统计口径

- 固定六行，以常驻槽位 StableKey 保存，不以对象名称或某一条生命的引用作为唯一身份。
- 击杀：干员给敌方干员造成致命的正伤害时给攻击者记 1 次；击杀小兵/塔不算干员击杀，无来源/友军伤害不记击杀。
- 死亡：干员真实死亡记 1 次，主动撤退不记死亡；同一生命最多计一次。
- 对塔伤害：干员对敌方指定防御塔造成的实际生命损失，包含过量伤害截断后的值；不统计原始面板伤害、小兵/塔伤害、友军或未命中弹次。
- 同一槽位跨死亡、撤退和再部署累计。新比赛六行全部归零。
- 从 `DamageTaken` 的正伤害通知记录致命命中，避免 `Died` 订阅顺序和 EditMode 即刻销毁尸体对事件产生影响。此事件发生时已扣血但尚未触发死亡。
- 继续遵守现有投射物目标合法性：攻击者死亡导致投射物取消时，不增加统计；不借统计功能改变战斗行为。
- 收集最终结算帧中现有合法投射物命中后，在最终结算通知时冻结独立只读快照；UI 读取快照而非继续读取活体。
- 监听在离场、重绑、销毁时正确解绑，不扫描每帧全部单位，不遗留静态统计跨场景。

## 最小 UI

- 游戏过程中顶部显示 `MM:SS` 和蓝/红塔当前/最大生命；与已有技能 HUD 共用 Canvas，不覆盖技能/部署反馈。
- 结算面板显示玩家蓝方视角的胜利/失败/平局、时长、双方塔最终血量与六名干员的阵营/名称/击杀/死亡/对塔伤害。
- 结果采用可读中文标签与固定六行；1920×1080 与 1280×720 下不越界，按钮可由鼠标点击。
- 结算后显示“退出游戏”按钮及己方同意人数（0/3 至 3/3）。比赛进行中不能发起退出投票；不提供重新开始按钮。
- 以己方三个常驻槽位 StableKey 作为投票身份，死亡或等待再部署的队友仍有一票，敌方票无效；重复投票不得重复计数。
- 玩家确认退出记一票；用户已确认两名电脑队友自动同意。只有三名同队成员全为同意才触发一次退出，不得只检查玩家确认或活体数量。
- 尚未全员同意时保留结算面板；退出不写输入绑定或重载比赛。Windows 文件版调用 Application.Quit，编辑器内停止 Play Mode；测试通过注入退出回调验证真实 Button 流程，不能退出测试运行器。
- 新启动/场景正常重载时仍产生全新比赛与归零数据，用于保证生命周期正确，不作为结果面板的重新开始功能。

## 场景与用户文件边界

- 直接在 `D:\arknights-frontline` 的 `dev`，不创建工作树；保留当前用户的材质、渲染、Packages、ProjectSettings、MinionLane 测试、未跟踪文档等。
- 当前 `PrototypeArena.unity` 在阶段 6 提交后再次被用户修改。先字节备份/记录哈希，再使用仅增加阶段 7 组件与引用的编辑器升级方法保存现有场景，保留既有对象、fileID、摄像机、材质引用及场景设置。
- 确定性完整构建器也接线同一运行时组件，供后续重建使用。本次以升级已有场景为主，避免丢失用户新场景调整。
- 用户此前已授权原有场景/摄像机改动随功能一起提交；对本轮新增且与功能无关的场景差异，先核对实际内容和可分离性，禁止借授权纳入其他类型用户文件。
- 运行时展示引导在现有 roster Awake 部署后初始化统计与 UI；启动的第一帧战斗前完成，场景重新加载无需编辑器接口。
